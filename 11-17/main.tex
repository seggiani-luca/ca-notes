\subsubsection{Anatomy of an exception}

Let's walk through all the 6 steps that take place when handling an exception.

\begin{enumerate}
	\item \textbf{Stacking}: first, what we said are the caller saved registers (which can be used as free scratch by subroutines) have to be saved. These were \texttt{r0-r3}, \texttt{r12}, \texttt{LR}, \texttt{PC} and \texttt{PSR}. They are saved in the currently used stack (MSP or PSP).

	      Then, MSP is always used during exception. Note that this can mean having to detect whether the last stack was PSP or MSP in the ISR, in order to fetch the original instruction data. This can be done by testing \texttt{LR} (see later);
	      PC and PSR are stacked first, so instruction fetch and PSR update can be started early;

	\item \textbf{ISR location}: now the NVIC puts the exception code on the data bus. The CPU uses the code as an index to access a vector named \textit{Interrupt Vector Table} (\textbf{IVT}). Each entry of the IVT manages an exception: it contains either one ARM instruction or an address in memory.. In the v7-M architecture, there are addresses of the exception service procedures;

	\item \textbf{Inbound register updates}: the following registers are updated when entering the exception handler (the same we stacked before):
	      \begin{itemize}
		      \item MSP or PSP (whichever was active): updated after stacking;
		      \item \texttt{SP} switches to MSP;
		      \item \texttt{PSR} (IPSR only): exception number;
		      \item \texttt{PC}: address of the exception handler;
		      \item \texttt{LR}: exception return information \texttt{EXC\_RETURN}: this is the address we have to jump back to to return to the correct stack (MSP or PSP), at the correct privilege level.

		            It is laid out as follows:
		            \begin{itemize}
			            \item Bit 0: processor state. 0 -> ARM, 1 -> Thumb
			            \item Bit 1: reserved, it must be 0
			            \item Bit 2: return stack. 0 -> MSP, 1 -> PSP
			            \item Bit 3: return mode. 0 -> handler, 1 -> thread
			            \item Bits 4-31: each bit must be 1
		            \end{itemize}

		            In practice, the allowed values of \texttt{EXC\_RETURN} are:
		            \begin{itemize}
			            \item \texttt{0xFFFFFFF1}: return to handler mode;
			            \item \texttt{0xFFFFFFF9}: return to thread mode with MSP;
			            \item \texttt{0xFFFFFFFD}: return to thread mode with PSP.
		            \end{itemize}

		      \item Some NVIC registers: pending status of exception is cleared, active bit of exception is set.
	      \end{itemize}

	\item \textbf{Handler execution}: this is the actual handler portion, defined by user code. Possible operations performed by the handler can be:
	      \begin{itemize}
		      \item Reading a fault status register (FSR) to know the cause of usage, bus, memory management fault;
		      \item Reading a fault address register (FAR) to know the memory location of a precise fault (bus or memory);
		      \item Reading the stacked program counter to retrieve the offending instruction (this has to be done even for normal syscalls called via \texttt{SVC}).
	      \end{itemize}
	\item \textbf{Unstacking}: registers pushed to the stack are restored in the same order they were pushed;
	\item \textbf{NVIC register update}: NVIC cleanup, the active bit of the exception is cleared. If the input of an external interrupt is still asserted, the pending bit is set again, so the handler is reentered.
\end{enumerate}
